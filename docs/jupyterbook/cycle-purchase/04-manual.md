# 使用手冊

以使用者角度說明每一頁怎麼操作。內容與站內手冊 `/cycle-purchase/manual`（v2.1）同源，
並依 2026-08-20 的程式碼重新核對。

## 一、先把主檔準備好

週採所有單據都建立在主檔上。主檔沒設好，請購單連料號都選不出來。

### 料號主檔 `/cycle-purchase/items`

集團統一的新編碼料號。**刻意不沿用**兩家公司原本的 E（工務）／C（清潔）／G（文具印刷）／S（營業）系列編碼。

```{admonition} 為什麼要另建一套料號
:class: caution

實測比對過：兩家公司料號字串相同的 115 筆裡，品名／廠商／單價三者完全一致的**只有 7 筆**。
「同代碼＝同品項」這個假設會出錯，所以另建集團料號，再用**料號對照表**把兩家公司的舊料號連過來。
```

### 料號對照表

對照表把「集團料號」對到「某家公司的舊料號＋單價」，並標記**屬於哪個部門**。
請購單的可選料號就是靠這張表按「公司＋部門」篩出來的。

```{admonition} 請購單選不到某個料號 ≠ 料號主檔沒建
:class: error

更常見的原因是對照表裡那筆的**公司或部門標錯了**，所以你的部門篩不到它。
```

### 四張支援主檔

| 主檔 | 用在哪裡 | 路徑 |
|------|---------|------|
| 部門主檔 | 請購單歸屬、彙整單部門別、費用分攤 | `/cycle-purchase/masters/departments` |
| 成本中心主檔 | 請購單選填、費用分攤 | `/cycle-purchase/masters/cost-centers` |
| 會計科目主檔 | 請購明細逐行手動選、費用分攤 | `/cycle-purchase/masters/account-codes` |
| 供應商主檔 | 彙整單指定廠商、採購單 | `/cycle-purchase/masters/vendors` |

```{admonition} 部門主檔的「承辦人」（owner_user_id）很重要
:class: caution

系統靠它判斷登入者屬於哪個週採部門。沒設的話，Dashboard 的「我的待辦」會是空的，
而且只勾 `cycle_purchase_request` 的人會編輯不了自己部門的請購單。
```

會計科目主檔如果是空的，系統啟動時會自動塞 4 筆預設值：工程備品、清潔用品、文具用品、營業用品（`CPAC-001`～`004`）。

### 週期設定 `/cycle-purchase/cycles`

定義採購週期（例如「每月」）。請購單建立時要掛在某個週期下。

早期設計有「批次」這一層（週期 → 批次 → 請購單），後來拿掉了。
週採真正的範圍界線是**料號主檔本身**——不在料號主檔裡的品項本來就選不到，不需要再用時間窗管一次。

## 二、請購單 `/cycle-purchase/requests`

1. 按「新增請購單」，選週期與部門（需要 `cycle_purchase_buyer` 權限）
2. 進入明細，從可選料號清單挑品項——清單已按你的公司＋部門篩好
3. 填數量。單價會從料號對照表自動帶入並**快照**下來
4. 逐行選會計科目（不從料號或部門自動帶，要自己選）
5. 填完就好，**不用按儲存、也不用送出**

```{admonition} 這一頁是改一格存一格的即時儲存
:class: caution

所以沒有「儲存」按鈕。每改一次數量或會計科目，系統就立刻寫進資料庫。
明細卡片標題旁會顯示「儲存中…」與「已自動儲存 HH:mm」。
好處是**填到一半直接關掉網頁也不會丟資料**。
```

### 三組明細工具

| 工具 | 做什麼 | 什麼時候用 |
|------|--------|-----------|
| 全部／只看已填 | 只顯示已經填了數量的料號 | 核對「這個月到底要買什麼」——一張單通常只填十幾筆 |
| 全部展開／全部收合 | 一次開關所有類別 | 不想一個個點類別標題 |
| 搜尋框 | 依料號或品名找 | 已經知道要找哪一項 |

三者可疊加。切到「只看已填」時會自動全部展開；搜尋時也會自動展開有結果的類別。

```{admonition} 在「只看已填」模式下把數量改成 0，那一列會立刻消失
:class: caution

因為它不再符合「已填」的條件。這是篩選器的正常行為，不是資料掉了。切換到「全部」就找得到。
```

- **同一個週期＋期別＋部門只能有一張請購單**。重複觸發「產生本期請購單」不會產生第二張（刻意設計成冪等）。
- 單價是**新增明細當下的快照**，之後改料號對照表的價格不會回頭改已填好的單。

### 關閉與重新開啟

2026-07-17 起**沒有簽核流程**了，只有「關閉」與「重新開啟」。
期別過了系統每天 00:05 會自動關（標籤是**淺粉色的「關閉」**），手動關只是為了提早定案。

已關閉的請購單需要 `cycle_purchase_close` 或 `cycle_purchase_view` 權限才看得到。
一般填單人的清單裡只會有「開放中」的單——**看不到不代表資料掉了**。

## 三、彙整單 `/cycle-purchase/summary`

1. 按「產生彙整」
2. 選「週期＋公司＋月份」，列出這個範圍內**還沒被彙整過**的請購單
3. **已關閉**的預設全選（可手動取消）；**未關閉**的也會列出來但勾不動，按該列的「關閉並納入」可直接關掉並勾起來
4. 確認後產生彙整列

彙整粒度是「**公司＋料號＋部門**」——同一個料號，不同部門各自成一列。

```{admonition} 未關閉的單為什麼不能勾
:class: note

**關閉才代表這張單的數量已經定案。** 如果讓開放中的單也能彙整，之後有人再去改請購數量，
彙整單的數字就默默錯了，而且沒有任何地方看得出來。
列出來只是為了讓你知道「那張單就在那裡，只差一個關閉動作」。
```

### 需求總量 vs 調整量

| 欄位 | 誰決定 | 說明 |
|------|--------|------|
| 需求總量 | 系統算 | 各已關閉請購單明細加總，不能改 |
| 調整量 | 採購改 | 預設等於需求總量；實際要跟供應商訂多少 |
| 調整原因 | 採購填 | 調整量 ≠ 需求總量時**必填** |

轉成採購單時，訂購數量取的是**調整量**。

### 再彙整一次會怎樣

- 同一個 key 已有 **draft**（還沒轉採購單）的彙整列 → 數量**累加**上去
- 同一個 key 已 **converted**（轉過採購單、鎖定）→ **另開一列**承接，不動舊列

## 四、採購單 `/cycle-purchase/pos`

從彙整單依供應商轉出，一供應商一張。詳情頁可改預計到貨日與備註。

「取消」與「退回彙整單」是兩件事，別選錯——見〈流程與狀態機〉。

## 五、驗收單 `/cycle-purchase/receiving`

一張採購單底下可以開多張驗收單，每次收到多少填多少。

| 欄位 | 意思 |
|------|------|
| 訂購數量 | 採購明細的數量，唯讀 |
| 先前已驗收數量 | 前幾張驗收單已收掉的量，系統自動帶 |
| 本次驗收數量 | 這一批實際收到多少 |
| 是否到此為止 | **針對這個料號**：勾起來＝不會再收了；不勾＝後面還有批次 |
| 差異數量 | 系統算：累計已收 − 訂購數量 |
| 差異原因 | 差異 ≠ 0 時**必填** |

```{admonition} 「是否到此為止」是關鍵
:class: important

不勾代表後面還有批次，這時候數量不足**不算異常**；勾了才會被當成真正的短交，並記進異常稽核紀錄。
```

`completed` 與 `discrepancy` 是送出時系統依明細自動判定的，**不能人工指定**，送出後會連帶重算採購單狀態。

### 進貨數量報表 `/cycle-purchase/receiving-report`

依月份＋公司＋供應商＋料號彙總驗收數量與金額。**只統計已送出的驗收單**（`completed`／`discrepancy`），草稿不算。

```{admonition} 日期快捷的基準日不是今天
:class: warning

六個快捷（本月／上月／最近 30 天／今年／去年／全部）以**最後一張驗收單的驗收日期**為基準
（`StandardRangePicker` 的 `anchor`，見 CLAUDE.md §8）。下拉選單底部會標明基準日。

「選了『本月』卻查不到資料」通常不是資料掉了——先看基準日：如果最後一張驗收單是上個月的，那「本月」本來就沒有東西。
```

## 六、請款單 `/cycle-purchase/payments`

請款單掛的是**採購單**，不是驗收單。建立時系統依驗收明細自動試算每個部門該負擔多少，填進「建議分攤金額」。

- 建議分攤與實際分攤兩個欄位**並存**，不是覆蓋——這樣才看得出調了多少、為什麼調
- 實際分攤 ≠ 建議分攤時，要填調整原因
- 分攤合計 ≠ 發票金額時，請款單本身要填差異原因

分攤明細的維度是「公司＋部門＋成本中心＋會計科目」，這也是為什麼請購明細那一步要**逐行選會計科目**。

## 七、常見誤解速查

| 誤解 | 實際 |
|------|------|
| 週採的部門跟人事系統／預算模組是同一份 | 不是。週採自己一套主檔 |
| 請購單要送出給主管簽核 | 2026-07-17 起已無簽核流程 |
| 單子一定要有人手動關閉 | 不用，期別過了系統每天 00:05 自動關 |
| 我看不到某張單，一定是資料掉了 | 已關閉的單需要 `cycle_purchase_close` 或 `cycle_purchase_view` 才看得到 |
| 轉成採購單就回不去了 | 回得去，用「退回彙整單」 |
| 不要的採購單按「取消」就對了 | 想重新調整再採購要用「退回彙整單」，按取消會卡住 |
| 清單裡沒出現＝系統漏抓 | 這些清單都不藏資料。真的沒出現通常是**已被彙整過** |
